# 河北尚学单招校区成绩分析

纯静态网页版成绩分析平台，覆盖龙泉校区与星耀校区。打开首页即自动读取对应校区的周测成绩 Excel，在浏览器本地完成全部统计与图表渲染。

**无后端、无数据库、无数据上传**：成绩文件只在本机浏览器内解析，不会发送到任何服务器。

---

| 文件 | 说明 |

| `tools/` | 构建与自动化测试脚本，不参与站点运行 |

## 功能

### 分值对齐（重点）

不同考试的满分可能不一致。实测龙泉数据中就存在：

| 班级 | 科目 | 8.2 入学测 | 8.8 周测起 |
| --- | --- | --- | --- |
| 1类 | 物理 | 245 | 105 |
| 1类 | 地理 | 105 | 45 |
| 2类2 | 总分 | 250（4 科） | 450（9 科） |

若直接比较，满分从 245 缩到 105 会被误读成「成绩暴跌」，科目从 4 门增到 9 门会被误读成「成绩暴涨」。

开启「对齐最高满分」后，系统以每个 **班级 × 科目** 历次考试中**出现过的最高满分**为基准，把其他考试的成绩按 `最高满分 ÷ 当次满分` 等比放大，使所有统计、图表、达标率与名次统一在同一尺度上。

选「最高」而非「最新」的原因：放大到最大尺度不会丢分辨率。若以最新的 105 为基准，入学测的 245 分制成绩折算后要压缩到 105 分制，细节被抹平；反向放大到 245 则保留全部精度，且满分最高的那次成绩原样不动。

- 表头未标注满分的「总分」，按该次考试各科标注满分之和自动推导
- 折算只影响页面计算，**不会修改 Excel 原文件**
- 顶部开关可随时关闭，还原查看原始分数；反复开关不会累积误差（每次从原始快照重算）
- 顶栏用一句话提示当前口径，例如「已对齐最高满分 · 31 项满分变动（1类 物理→245 等）」，正文不再铺明细表

当前龙泉校区共检测到 **31 项**满分变动，星耀校区因只有一次考试而无需折算。

### 自动读取成绩

打开页面即自动加载对应校区的成绩文件，顶栏实时回显数据源状态（文件名、班级数、考试次数、学生数）。找不到文件时给出手动上传引导，页面不会卡死。

支持多个候选文件名依次尝试，方便以后改名或把数据放进 `data/` 子目录：

```
27届龙泉周测成绩.xlsx
27届龙泉周测成绩.xls
龙泉周测成绩.xlsx
data/27届龙泉周测成绩.xlsx
```

也可随时点击右上角「上传 Excel」用新文件覆盖，支持多文件同时上传。

### 导出

按「**功能-班级/姓名**」自动命名，例如：

```
全班成绩-1类.pdf
个人趋势-安一航.pdf
名次变化-1类+2类1+2类2等15班.pdf
```

- **PDF**：**A4 横向**，比纵向多约 40% 横向空间，宽表与图表更完整；导出时自动放宽内容区到表格真实宽度，横向滚动区不会被裁切，并自动分页。页首附导出抬头（校区 / 功能 / 时间 / 对齐口径）。导出结果不含背景特效、页签与操作按钮
- **Excel**：把当前页面表格原样导出，适合二次加工（纵向横向无差别）

合并页导出时取当前所在子功能的名称。

## 视觉

首页、两个校区页与占位页共用同一套设计语言：浅色简约 + 毛玻璃质感 + 大号数字突出数据，粒子背景在页面不可见时自动暂停。

响应式按三档适配，手机竖屏（≤700px）下顶栏纵向堆叠、页签与分段按钮占满整行、筛选下拉铺满宽度、表格与指标卡自动降列，横屏矮屏（≤560px 高）取消吸顶以让出纵向空间。数据表格本身列数多，保留表格内部横向滚动——这是刻意为之，强行压窄会让数字挤成一团。

## 部署到 GitHub Pages

### 为什么需要 `.nojekyll`

GitHub Pages 默认用 Jekyll 处理站点，而 Jekyll 会**忽略所有以 `_` 开头的文件和目录**，并可能对中文文件名做额外的路径编码处理。本项目的页面与成绩文件都是中文名，加上 `tools/` 等目录，关闭 Jekyll 后原样发布最稳妥。`.nojekyll` 内容为空，只是一个标记文件，**不要删除**。

### 步骤

```bash
# 1. 初始化仓库（在项目根目录执行）
git init
git add .
git commit -m "校区成绩分析 v4.0.0：统一视觉、功能重组、分值对齐"

# 2. 关联远端（替换成你自己的仓库地址）
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main

# 3. 推送
git push -u origin main
```

推送后到仓库 **Settings → Pages**：

- Source 选 `Deploy from a branch`
- Branch 选 `main`，目录选 `/ (root)`
- 保存，等待构建完成

访问地址为 `https://<你的用户名>.github.io/<仓库名>/`。

### 部署前自查清单

- [ ] 成绩 Excel 与页面 HTML 在**同一目录**（自动加载按相对路径读取）
- [ ] `.nojekyll` 已提交（`git status` 能看到，未被忽略）
- [ ] 中文文件名已正确提交（`git ls-files` 检查是否出现转义或乱码）
- [ ] `tools/` 下的 `node_modules/`、`*.log` 未被提交（已在 `.gitignore` 中排除）

### 关于中文文件名

中文名在 HTTP 下需要 percent-encode，现代浏览器会自动处理，实测访问与自动加载均正常。若你的部署环境（某些 CDN、Windows 服务器或旧版 Git 客户端）对中文名支持不佳，可改用拼音名并同步修改三处：

1. 文件名本身
2. 页面内 `CAMPUS_CONFIG` 的 `name` / `dataFile` / `dataCandidates`
3. `index.html` 的 `CAMPUSES` 数组与卡片 `href`

若使用 Git for Windows，建议先执行 `git config core.quotepath false`，否则中文文件名在 `git status` 中会显示为转义序列。

## 更新成绩数据

把新的成绩文件覆盖同名文件即可，无需改代码。下次打开页面会自动读取。

若新文件的**满分发生变化**（例如语文从 100 改成 150），只要表头按 `科目（满分）` 格式标注，分值对齐会自动生效，历次成绩仍可正确比较。

若文件名变了，修改页面内 `CAMPUS_CONFIG.dataFile` 与 `index.html` 的 `CAMPUSES` 数组即可。

## 本地开发与测试

```bash
# 重新构建两个校区页（改完母版或样式后执行）
python tools/build.py

# 运行自动化测试（需要 Node.js）
cd tools
npm install
node verify.mjs        # 静态检查：语法、页签一致性、默认值、改造点
node e2e.mjs           # 校区页端到端：真实数据下的渲染、分值对齐与 PDF 横向导出
node e2e-home.mjs      # 首页端到端：统计口径、精简后结构与降级路径
node http-test.mjs     # HTTP 场景：中文文件名与自动加载
node preflight.mjs     # 部署前检查：全站语法、链接有效性、两页差异行数
```

### 构建机制

两个校区页**只由 `CAMPUS_CONFIG` 的三行配置区分**，其余代码完全相同。`tools/build.py` 以 `tools/template-v3.4.html` 为母版，套用 `tools/style.css` 并注入各项功能改造，一次生成两个文件。

每处替换都做精确匹配校验，任何一处未命中都会中断构建并报错，不会产出半成品。

> **请勿手工分别编辑两个校区页**，否则两份代码会再次分叉。需要改动时请改母版或构建脚本，然后重新构建。

当前测试共 **272 项断言**全部通过，其中包含用真实成绩数据对折算结果的独立复核：1类 安一航 物理，入学测满分 245 时原分 111 保持不变（它正是最高满分那次），周测满分 105 的 40 分放大为 93.3 分，与手算 `40 × 245 ÷ 105` 一致。

同时覆盖 PDF 导出为 A4 横向（版心 281mm）、超一页自动分页、导出后页面状态完整复原。
